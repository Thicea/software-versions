# software-versions

Windows Server 2022 関連ソフトウェア33項目の調査結果を掲載する静的サイトです。ビルドや外部ライブラリ、APIキーは不要です。調査済みの値と、公式情報を取得できなかった項目を区別して掲載します。現在の調査範囲と制約は `research/2026-11-09-network-restored.md` を参照してください。

## ローカル表示

リポジトリのディレクトリで実行します。

```sh
python3 scripts/render.py
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザーからローカルのポート8000を開きます。`index.html` は調査結果を含む単独のHTMLです。JavaScriptを使わず表示できます。

## 手動で調査結果を更新する

1. 指定の調査プロンプトで、その実行時点の全33項目をオンライン調査します。出力は指定どおりのMarkdown表にします。
2. 公式原文と照合した結果を `versions.json` に転記します。製品名もこのファイルで管理します。指定系列、CPUアーキテクチャ、CU/GDRを区別してください。
3. `checkedAt` に実際の調査日時をタイムゾーン付きで設定します（形式例：`2026-11-09T18:30:00+09:00`）。ファイル編集日時や公開日時で代用しないでください。
4. `python3 scripts/render.py` を実行します。33項目の形式検証後、`templates/index.html` と調査データから `index.html` を生成し、`products.json` の製品名・順序もそろえます。ページ表示も確認します。
5. 変更をコミットし、`main` にプッシュします。`versions.json` だけを更新した場合も、後述のActionsがページと製品一覧を自動生成して公開します。
6. GitHub Pagesのデプロイ成功と、公開ページの調査基準日時・更新内容を確認します。ユーザーから公開保留の指示がない限り、ここまでをサイト更新作業の完了範囲とします。

各項目の形式：

```json
{
  "no": 1,
  "name": "Microsoft Visual C++ 2013 Redistributable (x86)",
  "version": "今回未確認",
  "releaseDate": "未確認",
  "sources": [
    {"label": "公式参照先（未確認）", "url": "https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist"}
  ]
}
```

- `version`：確認したバージョン・KB・ビルド。確定できない場合は「最新版未確定」、今回確認できない場合は「今回未確認」。必要な短い注記もここに記載します。
- `releaseDate`：正式公開日を `YYYY/MM/DD` で指定。不明は「未確認」。ページ更新日と混同しないでください。
- `sources`：公式URLを配列で指定。不一致があれば両方を掲載し、リンク名で言語や掲載値を区別します。取得できた公式情報と取得不可の参照先を、リンク名で区別してください。
- 公式URL欄には、公式の説明・リリースノート・KB・配布案内などの参照ページを掲載します。インストーラー・圧縮ファイル・生のメタデータなど、ファイルへの直接リンクは掲載しません。調査で使う配布ファイルやメタデータのURLは実行証跡に保存します。
- No.33の掲載URLはWindows Server 2022向け.NET Framework 3.5／4.8専用のKB記事に限定します。4.8.1向けの情報が混在するまとめ記事・更新履歴は掲載しません。
- No.15・16はAgent単体の公開値や製造元・系列を確認できていません。候補資料は同一製品と確認済みの情報として扱わないでください。
- 過去参考の記述・バージョンは掲載しません。生成コマンドは該当記述があるデータを拒否します。
- 調査基準日時は保存した固定の日時を日本時間で表示します。閲覧日時・生成日時へ自動的に置き換えません。
- 検証コマンドはデータ形式を検査します。最新版・公開日・公式サイトかどうかの正しさは判定しません。

## 製品名を変更する

表示名の基準は `versions.json` の各項目の `name` です。GitHub上でこのファイルだけを編集し、`main` にコミットすると、Actionsの `Publish site from versions.json` が `index.html` と `products.json` を生成・コミット・プッシュし、Pagesの公開内容との一致まで確認します。`products.json` と `index.html` は生成物なので、直接編集する必要はありません。

この表示更新では調査を再実行せず、バージョン・正式公開日・調査基準日時を保持します。No.1～33の番号と掲載順は維持してください。表示名を変えても、調査対象の指定系列（ODBC 17、OLE DB 18、SSMS 20、.NET 8など）は変わりません。調査対象の変更には取得処理の変更も必要です。

## GitHub Pagesで公開する

リポジトリ管理者が GitHub の **Settings → Pages → Build and deployment** で以下を選択します。

- Source: **Deploy from a branch**
- Branch: **main**、フォルダー: **/ (root)**

保存後、GitHub側のデプロイ完了を確認し、Pages設定画面に表示されるURLを開いてください。「今回未確認」「最新版未確定」の項目は、最新版を確認済みという意味ではありません。公開元へのプッシュ後、GitHubのActionsでPagesのデプロイ結果を確認してください。

パッチ適用・サーバーへのインストール処理は含みません。


## 平日朝8:30の自動更新

GitHub Actionsの `Refresh software versions` が、**月～金の08:30（日本時間、祝日を含む）** を実行予定時刻として動作します。UTCでは日～木の23:30なので、cronは `30 23 * * 0-4` です。GitHub側の混雑等で開始が遅れる場合があり、厳密な時刻保証はありません。

8:30の起動遅延・実行漏れ・調査失敗に備え、同じ平日の08:45と09:15にも再試行します。当日08:30以降の調査が完了済みなら再調査・日時更新を省略し、公開状態の確認のみ行います。公開処理だけが失敗した場合も、この再試行で既存の調査結果の公開をやり直します。再試行もGitHubの予約実行なので、8:30ちょうどの更新や開始時刻は保証できません。

自動実行は、全33項目の指定した公式情報の再取得、製品・系列別の検証、データ更新、`main` へのコミット・プッシュ、Pagesのビルド要求、公開HTMLの内容一致確認まで行います。外部APIキーは不要で、GitHubが実行ごとに発行する `GITHUB_TOKEN` を使います。

自動更新で変更するのは、次の3種類だけです。

- 各製品のバージョン・KB・ビルド欄（`version`）
- メーカーの正式公開日（`releaseDate`、不明な場合は「未確認」）
- 上部の日本時間の調査基準日時（`checkedAt`）

定期調査は、ユーザーが `versions.json` に設定した製品名・項目数・順序・公式URL・リンク名・レイアウトを保持します。定期調査のコミット対象は `versions.json` と、それから生成した `index.html` の2ファイルに限定し、変更範囲も検査します。固定の公式URLには特定バージョンのリンクも含まれるため、毎回の最新版判定に使用した実際の参照先は、その実行の証跡JSONで確認してください。

- 指定メジャー、正式版とプレビュー、x86/x64、SQL ServerのCU・CU＋GDR・GDR、.NET Framework 4.8と4.8.1を区別します。
- No.15・16・23・25は、単体の公開値や製造元を確定できる追加情報が揃うまで「最新版未確定」とします。各回に現在の公式参照先へ接続し、別製品や親パッケージの版を転用しません。
- 取得・判定に失敗した場合は、版・日付・調査基準日時を書き換えず、プッシュしません。公開確認の失敗もActions上の失敗として表示します。
- 取得したURL・日時・ハッシュ・判定結果はActionsの `software-research-...` アーティファクトに14日間保存します。インストーラーは詳細バージョンの読み取りにのみ使い、実行・インストールしません。
- メーカーのページ構造・参照先が変わった場合は、取得処理のメンテナンスが必要です。

GitHubの **Actions → Refresh software versions → Run workflow** から、当日の調査が完了済みでも手動で再調査できます。ワークフローの設定ファイルを変更したときも設定検証のため実行します。運用停止は同じActions画面の **Disable workflow** で行えます。

ローカルで取得処理を試す場合（公開・ファイル変更なし）：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
PYTHONDONTWRITEBYTECODE=1 python3 scripts/refresh.py --dry-run --report /tmp/software-research.json
```
